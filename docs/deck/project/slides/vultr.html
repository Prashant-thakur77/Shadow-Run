Built on Vultr, and honest about its limits

Vultr services

VX1 runs the rehearsal microVMs on KVM

Cloud Compute runs the control plane, web app and MCP server

Serverless Inference serves every LLM call

Managed Postgres is the demo production database

Object Storage keeps evidence and backups

VPC keeps the runner private

What it can’t do

Email, Stripe and cloud API calls can’t be rehearsed. They’re blocked, or a person decides.

If no guardrail encodes a rule, a person has to notice the diff.

What’s on the auto-apply list can change badly, up to the limit, with no person looking.

Clone cost grows with database size. Thin clones aren’t built yet.

PII isn’t masked in the clone yet.

github.com/Prashant-thakur77/Shadow-Run. One script builds it all from zero, one removes it.

Ends where the pitch started: your agent wants to touch prod, so let it break a clone first. The whole stack is created by infra/provision.py and removed by infra/teardown.py, which confirms each resource returns 404.
